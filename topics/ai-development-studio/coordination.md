# 项目经理与任务调度

状态：我的构想，角色和交接方式待讨论。首次整理：2026-11-08。

## 我的构想

我直接和一个项目经理智能体说话，它自己调动对应的电脑去干活。

任务下发之后，我能看到对应电脑上的 Codex、Claude Code 终端继续细化和执行。中央对话与各台机器上的工作现场能够联系起来。

每台电脑上的团队专精自己的项目。多个项目可以同时工作，一个项目里也可以有多个智能体。

还有一种很有意思的分工：一台电脑做规划，另一台电脑执行细化。它是可以探索的协作形式，目前没有决定所有任务都这样分。

## 讨论中的建议

以下是 48 的补充，尚未形成固定职责：

- 项目经理协调目标、优先级、跨项目依赖，以及需要我决定的事情。
- 项目团队负责结合当前代码调查、细化、实现和验证。
- 我可以绕过中央入口，直接参与某个项目；现场的新决定应能同步回来。
- 执行团队发现计划与事实不符时，能够反馈证据并推动计划调整。
- 每项任务都能追到实际执行会话、代码修改和验证结果。

## 还没决定的问题

- 项目经理需要理解到什么深度，哪些细节交给项目团队？
- 团队在忙时，新任务怎样排队、插队或暂停？
- 怎样避免同一任务被重复执行，或者多个智能体覆盖同一份改动？
- 中央入口下发的任务，怎样对应到我能看见、能接管的终端会话？
- Codex、Claude Code 等工具之间，任务和状态怎样交接？
- 项目经理或执行机器中断后，谁接着处理？
- 规划与执行怎样反馈，什么任务值得分到不同电脑？

连接协议、调度框架、账户方案和预算都还没决定。
